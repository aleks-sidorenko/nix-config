# AGENTS.md

Guidance for coding agents working in this repository.

## Overview

NixOS hosts declared with [den](https://den.denful.dev/), a dendritic
flake-parts layout. Every `.nix` file under `modules/` is a flake-parts module
loaded by import-tree; `_`-prefixed files and directories are helpers the
loader skips. `flake.nix` is generated by flake-file.

Four den concepts; read den's docs, not this file, for how they work:

- **Entities**: hosts (`den.hosts.<system>.<name>`) and users
  (`den.hosts.<system>.<name>.users.<user>`, content in `den.aspects.<user>`).
- **Aspects**: units of configuration, `den.aspects.<path>`, with a class body
  per target (`nixos`, `homeManager`) and `includes`. An entity gets an aspect
  by including it; `den.schema.<kind>.includes` and `den.default` attach one
  to every entity of a kind.
  See [overview](https://den.denful.dev/overview/) and
  [settings](https://den.denful.dev/guides/aspect-settings/).
- **Policies**: `den.policies` and batteries like
  `den.batteries.mutual-provider` that shape the entity topology: which
  entities provide to which (`provides.to-hosts`).
- **Quirks**: untyped collections aspects contribute to and class bodies read
  (`den.quirks`; see [quirks](https://den.denful.dev/guides/quirks/)).

What exists and why it is shaped this way is in
[docs/architecture.md](docs/architecture.md); what `server` runs, in
[docs/homelab.md](docs/homelab.md). This file holds the rules and recipes for
changing it; update those docs in the same change when what they describe
changes.

## Designing modules

Every module shares through `config` alone, so any file can move or go
without breaking another.

- **Imports stay in the folder.** Import only `_` files in your own folder
  (`import ./_arr.nix { inherit den; }`). Never `import ../…`: when a second
  folder needs a helper, the module that owns it publishes it as a
  read-only option and readers take it from `config`. The
  `naming-imports-stay-in-folder` eval test enforces this. Reading repo data
  outside `modules/` by path (`identities/`, `secrets/`) is fine.
- **Pick the mechanism by what is shared**, from the table below (den's
  [choosing a mechanism](https://den.denful.dev/explanation/choosing-a-mechanism/)).
- **Write each fact once.** Near-identical aspects come from one `_`
  factory that returns the whole aspect (`_arr.nix`), not from copied
  files. Derive what can be derived (`host.name`, `host.primaryUser`)
  instead of repeating the literal.
- **One owner per value.** The module that owns a value declares its
  option, quirk or setting; consumers never redeclare or hard-code it.
- **Size an aspect by what a host includes or drops alone.** A tool gets
  its own aspect when it has configuration, an input, settings, a
  platform body or a test of its own (`cli.htop`, `cli.nix-index`); a
  bare `programs.<x>.enable` counts as a package, not configuration.
  Group by coupling, never by label: one aspect when the parts only work
  together (`cli.media`: the scripts need ffmpeg and `MEDIA_HOME`), one
  bucket for plain unconfigured packages (`cli.utils`). A tool's shell
  shortcuts live in its aspect, not the shell's. No
  `cli.monitoring`-style buckets of unrelated configured tools; a role is
  the grouping view, and a crowded folder takes variants
  (`<category>.<feature>.<variant>`), not merged aspects.

## Where things go

| Need | Mechanism | Place |
| --- | --- | --- |
| Reusable config for one concern | feature aspect | `den.aspects.<category>.<feature>` in `modules/<category>/<feature>.nix` |
| A bundle of features | role aspect | `den.aspects.roles.<role>` in `modules/roles/<role>.nix`, `includes` only |
| Applies to every host / user | schema include | `den.schema.host.includes` / `den.schema.user.includes` in `modules/den.nix` |
| Per-host value an aspect needs | setting | `settings` on the aspect that reads it; set in `den.hosts.<system>.<host>.settings.<category>.<feature>`. Read only your own settings or an included aspect's; never `den.schema.conf`, which reaches users and homes too |
| Per-host fact for any aspect (stateVersion, primaryUser, deploy) | host option | `den.schema.host.options` |
| Config and settings several aspects build on | shared aspect | an aspect each of them `includes` (den includes it once), e.g. `services.media` (media root, group) |
| Data many aspects contribute and one collects | quirk | `den.quirks.<name>` beside the collecting aspect; values may be `{ host, ... }:` or `{ config, ... }:`; the ones in use follow |
| State kept across reboots | `persist` quirk | `persist.directories` / `persist.files` in the aspect |
| Throwaway state the guard must accept | `persist` quirk | `persist.ignore` in the aspect |
| A service nginx proxies to | `vhosts` quirk | `vhosts = [ { name; port; … } ];` in the aspect; served at `<name>.<domain>`, nginx's `domain` setting (`modules/services/nginx.nix`) |
| Offsite backup paths or excludes | `backup` quirk | `backup = { paths; exclude; };` in the aspect (`modules/services/restic.nix`) |
| Extra install-test assertion | `installChecks` quirk | Python snippets in the aspect |
| Test-VM-only config an aspect needs | `installTest.extraConfig` | inside the aspect's `nixos` body |
| User-owned system config (password secret) | `provides.to-hosts` | user-side aspect, `modules/security/user-password.nix` |
| Host identity and its tests | host module | `modules/hosts/<host>/default.nix` (`_` helpers beside it) |
| Values several hosts share | module setting those hosts | `modules/hosts/<group>.nix`, e.g. `home-servers.nix` sets `server` and `server-vm` |
| Flake outputs, checks, tooling | flake-parts module | `modules/flake/<name>.nix` |
| A program of our own (scripts, a derivation with no host data) | package | `packages/<name>/package.nix` in callPackage form, with its tests as `checkPhase`; `modules/flake/packages.nix` exposes every folder as `packages.<system>.<name>`, `checks.<system>.package-<name>` and `overlays.default`. The aspect that installs it adds the overlay (`modules/cli/media.nix`) |
| A helper one folder uses | `_`-prefixed file | beside its readers, e.g. `modules/services/_media.nix` |
| A helper several folders use | read-only option | declared by the module that owns it, e.g. `config.installTests` (`modules/flake/install-tests.nix`), `config.isReservedKey` (`modules/den.nix`) |
| Names the aspects of one category must agree on | `_`-prefixed helper | `modules/<category>/_<name>.nix`, e.g. `modules/storage/_layout.nix` (disk label, subvolume names); data crossing categories goes through quirks, settings or host options |
| A homebrew cask or brew | the app aspect's `darwin` body | `homebrew.casks` / `homebrew.brews` in the aspect that owns the app (`modules/gui/raycast.nix`); `system.homebrew` only sets the policy |
| A per-project toolchain | stack | an entry in `dev.stacks` (`modules/dev/stacks.nix`), used from a project's `.envrc` with `use_stack <name>`; never a global package or variable. A launcher that runs the version the project pins (bazelisk, `dev.bazel`) may be global |
| A per-person fact (keys, name, email, GitHub accounts) | identity data | files in `identities/<id>/`, loaded once by the `identity` user option (`modules/den.nix`, defaults to the user's name); aspects read `user.identity.sshKey`, `.git.email`, … and never the folder |
| Secrets | SOPS | `secrets/nixos.yaml` (NixOS hosts), `secrets/darwin.yaml` (darwin hosts); recipients in `.sops.yaml` |

An aspect in `den.schema.<kind>.includes` reaches the host, but its
`homeManager` body does not reach users: only aspects in the host's include
tree are routed to them (`den.batteries.host-aspects`). Include such an aspect
from a role as well, as `security.ssh` is in `roles.workstation`.

Hostnames, usernames, `/persist` and domains appear only in `modules/hosts/`,
`modules/users/`, entity declarations and option defaults, never in a feature
aspect. The persistence root is the `storage.impermanence.root` setting; read
it, never write the path.

## Naming

- `den.aspects` top level holds only hosts, users (`<user>@<host>` for one
  host's account) and categories.
  Categories: `system`, `storage`, `security`, `services`, `hardware`,
  `roles`, `cli` (a terminal tool), `dev` (working on code), `gui` (a GUI
  app). A category names a concern, never a platform; a platform-only aspect
  has only that class's body.
- Feature: `den.aspects.<category>.<feature>` mirrors
  `modules/<category>/<feature>.nix` (or `<feature>/default.nix` when it has
  variants or helpers). Variant: `<category>.<feature>.<variant>` mirrors
  `modules/<category>/<feature>/<variant>.nix`.
- A category holds nothing itself and is never included. No namespace.
- A category past ~15 features splits into sub-groups by concern
  (`dev.editors.*`, `dev.build.*` in `modules/dev/editors/`), never by
  platform; a sub-group, like a category, holds nothing itself and is
  never included.
- Hosts and users are never named after a category.
- No path segment may be a den reserved key: `name description meta includes
  excludes admits policyEnforcement provides policies into classes _module _`,
  anything starting `__`, `settings`, any class (`nixos darwin homeManager os
  user hjem maid wsl`), any quirk
  (`persist installChecks vhosts backup`). Declaring a new
  quirk or class reserves its name too.
- Include named aspects (`den.aspects.system.nix`), never inline modules in
  `includes`.

`modules/flake/naming.nix` enforces this with eval tests; `just check` fails
on a violation.

## How to add

Stage new files (`git add`) before `just check`.

### A feature

1. Create `modules/<category>/<feature>.nix` with
   `den.aspects.<category>.<feature> = { nixos = …; };`. The file path mirrors
   the attribute path.
2. Declare each flake input it needs in the same file
   (`flake-file.inputs.<name>.url = "…";`), then `just flake-write`.
3. Include it from a role (`modules/roles/*.nix`), a host aspect, or
   `den.schema.<kind>.includes` in `modules/den.nix` if it applies to all.
4. State that survives reboot: `persist.directories = [ … ];`; throwaway
   state: `persist.ignore = [ … ];`. Every non-empty entry under `/var/lib` or
   `/var/cache` the service writes must be one or the other.
   A proxied service: `vhosts = [ { name = "…"; port = …; } ];` (optional
   `requiresProxyAuth`, `proxyWebsockets`, `clientMaxBodySize`, `locations`).
   Offsite backup: `backup = { paths = [ … ]; exclude = [ … ]; };`, or
   `backup = { host, ... }: { … };` when it depends on the host (a quirk value
   may be a function den calls per host; see `modules/services/calibre-web.nix`),
   or `{ config, ... }:` when it depends on the host's evaluated config (see
   `installChecks` in `modules/services/nginx.nix`).
   Excludes are absolute paths of persisted state, not globs: restic resolves
   them under the persistence root, so anything else silently matches nothing.
   An install-test assertion: `installChecks = [ ''machine.succeed("…")'' ];`.
   A test-VM accommodation (no network, no real secrets):
   `installTest.extraConfig.<option> = lib.mkForce …;` in the `nixos` body
   (see `modules/services/tailscale.nix`).
5. Add `evalTests.<name> = { expr = …; expected = …; };`, `<name>` a unique
   descriptive name, beside what it pins: the feature's own file for
   behaviour on every host that includes it (see
   `modules/services/tailscale.nix`), the host or user module for one entity
   (`modules/hosts/*/default.nix`, `modules/users/*.nix`), `modules/flake/*.nix`
   for outputs and tooling.

### A host

1. Create `modules/hosts/<host>/default.nix` with
   `den.hosts.<system>.<host> = { users.<user> = { }; stateVersion = "…"; settings.storage.disko.device = "…"; };`
   and `den.aspects.<host>.includes = [ den.aspects.roles.<role> … ];`.
2. Hardware-specific config goes in `modules/hosts/<host>/_hardware.nix`,
   imported via the host aspect's `nixos.imports`.
3. deploy-rs node: `deploy = { };` on the host logs in as its `primaryUser`
   (the only user unless set; optional `deploy.sshUser`, `deploy.hostname`).
   `deploy = null` (default) means no node;
   `modules/flake/deploy.nix` derives `interactiveSudo` from
   `security.sudo.wheelNeedsPassword`.
4. Add the host key to `.sops.yaml`, then `sops updatekeys secrets/nixos.yaml`.
5. Add eval tests beside it. A host replacing a live one needs a parity test
   like `modules/hosts/server/_parity.nix`.

### A VM host

1. As a host, named `<name>-vm` for the host it stands in for, including
   `den.aspects.hardware.qemu-guest`, with
   `settings.storage.disko.device = "/dev/vda"`.
2. `modules/flake/install-tests.nix` adds `checks.install-<host>` for every
   host including `qemu-guest`; no extra wiring.
3. Add an eval test that `config.allSystems.x86_64-linux.checks ? install-<host>`.
4. The install test itself runs in CI only (`just vm-test <host>` needs
   x86_64 KVM).

### A darwin host

1. `den.hosts.aarch64-darwin.<host>` in `modules/hosts/<host>/default.nix`,
   with the string `stateVersion` homes read.
2. darwin's own integer release goes in the host aspect:
   `den.aspects.<host>.darwin.system.stateVersion = <int>;`.
3. `just build <host>` builds `darwinConfigurations.<host>.system`; switch with
   `nix run .#<host> -- switch`.

### A user

1. `den.hosts.<system>.<host>.users.<user> = { };` in the host module.
2. `modules/users/<user>.nix`: `den.aspects.<user>.includes = [ … ];`
   (`den.batteries.primary-user`, `den.batteries.user-shell "fish"`, …).
   A user is a person: the same person under another account name on one
   host is `users.<user>.userName = "…"` there, not a second user, and what
   only that host's account needs goes in `den.aspects."<user>@<host>"` in
   the same file (`modules/users/alexander.nix`).
3. Public keys in `identities/<user>/`; the password hash as
   `user-<user>-password` in `secrets/nixos.yaml` (`sops secrets/nixos.yaml`).
4. Eval test beside the user (groups, shell, key).

### A setting

1. In the aspect: `settings.<name> = lib.mkOption { type; default; description; };`
   (see `settings.root` in `modules/storage/impermanence.nix`; others:
   `system.locale.timeZone`, `system.stylix.flavor` and `wallpaper`,
   `services.nginx.domain`, `services.media.root`,
   `services.restic.bucketUrl`, minecraft's `ops`, `whitelist`, `gamerules`,
   `serverProperties`). Read only your own aspect's settings, or those of an
   aspect you include.
2. Read in a class body: `host.settings.<category>.<feature>.<name>`.
3. Override per host: `settings.<category>.<feature>.<name> = …;` on the
   `den.hosts.<system>.<host>` entry.

### A quirk

1. `den.quirks.<name>.description = "…";` in the file of the aspect that reads it.
2. Contribute from aspects as `<name> = [ … ];`; read it by taking `<name>` as
   a class-body argument (see `persist` in `modules/storage/impermanence.nix`).
3. Its name is now reserved; `just check` reports any existing path segment
   that clashes.

### An input

1. Declare `flake-file.inputs.<name>.url = "…";` in the module that uses it,
   with `inputs.nixpkgs.follows = "nixpkgs";` where the input has one.
2. `just flake-write`; stage `flake.nix` and `flake.lock`.
3. Never hand-edit `flake.nix`; `just check` fails when it is stale.

## Rules

- No `enable`-gated aspects, no `mkIf` on roles: a host gets a feature by
  including it.
- No `specialArgs`, no `with`, no legacy den API (`provides`/`_` other than
  cross-entity keys like `provides.to-hosts`, `den.ctx`, `den.lib.parametric`,
  `den.base`).
- No hostname, username, `/persist` path or domain in a feature aspect.
- No `._` in aspect names; helpers are `_`-prefixed on disk only.
- `/home` is its own persistent subvolume; the only persistence quirk is
  `persist`. `installChecks` holds install-test Python only. Only the
  undeclared-state guard writes `disko.tests.extraChecks` directly
  (`mkOrder 1600`, after the harness's settle and failed-units checks at
  `mkAfter`): it must run last to see the state every earlier check made a
  service write, while the quirk runs in include order.
- State a service writes must be persisted or ignored: the install test's
  undeclared-state guard (`modules/storage/impermanence.nix`,
  `_persist-guard.py`) fails every install test on a non-empty entry under
  `/var/lib` or `/var/cache` that is neither.
- An aspect owns its install-test accommodations (`installTest.extraConfig`,
  declared by `storage.disko`); hosts and the harness do not special-case
  aspects.
- A failed unit fails every install test. The harness allows only each
  user's home-manager unit, which every test VM fails for a reason of its
  own (`modules/flake/install-tests.nix`).
- `server`'s disk must keep matching the snowfall tree's layout (parity tests); change it
  deliberately, together with the parity fixtures.
- Never commit secrets; respect SOPS. Move secrets files, do not re-encrypt.
- Install tests run in CI only. On darwin `just check` evaluates them without
  building.

## Secrets

- Edit with `sops secrets/nixos.yaml`; recipients are in `.sops.yaml`.
- After adding a host's recipient: `sops updatekeys secrets/nixos.yaml`.
  Never re-encrypt by hand.
- The install test generates its own secrets, encrypted to a throwaway age
  key, so CI never decrypts with a real host key. The host-key → sops path on
  the second boot is covered by the interactive install rehearsal (next
  slice), not by CI.

## Commands

Recipes use the dev shell directly when inside `nix develop` and fall back to
it otherwise.

```bash
just check            # format-check + lint + flake-check (stale flake.nix, eval tests)
just format [path]    # nix fmt (writes)
just format-check
just lint             # statix + deadnix
just lint-fix
just flake-write      # regenerate flake.nix from flake-file.inputs
just flake-check      # nix flake check
just build <host>     # build a host's toplevel
just deploy <host> [args]  # deploy-rs, built on the target; `--boot` activates on next boot
just vm-test <host>   # install test; x86_64 Linux with KVM only (exits 1 elsewhere)
just update [input]   # nix flake update
nix run .#<host> -- switch   # nh wrapper per host
```

Recipes are `<group>-<suffix>`; within a group every suffix is the same kind
(verbs for resource groups: `format-check`, `lint-fix`). Rename old recipes
instead of aliasing.

Updating den: `just update den`, read den's
[whats-changed](https://den.denful.dev/whats-changed/), fix what it names,
`just flake-write`, `just check`; one PR.

Debugging: `nix eval .#nixosConfigurations.<host>.config.<path>`; see den's
[debug guide](https://den.denful.dev/guides/debug/).

## Code style

- `inherit` over `with`; no `with` anywhere.
- Comments say why, not what; terse, no vendor or host names.
- Stage new files before evaluating: flakes ignore untracked ones.
- `just format` before each commit.
- Match surrounding style.

## Git

- Conventional Commits: `<type>[(scope)][!]: <description>`; types `feat fix
  docs refactor chore test style ci perf build`.
- Branches `<type>/<short-kebab-description>`, named after the goal; PRs are
  based on `master` with a Conventional Commits title.
